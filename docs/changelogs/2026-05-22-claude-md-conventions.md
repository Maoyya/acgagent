# 2026-05-22 CLAUDE.md 项目规约新增

## 变更原因

项目已进入多模块协同开发阶段（user、auth、agent），需要统一编码规范和变更管理流程，确保团队和 AI 助手在开发过程中遵循一致的约定，保障系统的安全性和稳定性。

## 变更内容

在 `CLAUDE.md` 末尾新增"项目规约"章节，包含以下八个子章节：

1. **安全可靠（最高优先级）** — 敏感信息处理、SQL 注入防护、接口鉴权、输入校验、向前兼容等
2. **代码注释** — 类/方法/行内注释规范，区分必要注释和废话注释
3. **架构与设计原则** — 三层架构职责、单一职责、依赖注入、面向接口编程等
4. **复用性与扩展性** — 复用优先、VO/DO 分离、配置外部化、模块模式一致
5. **变更管理** — 小步提交、Commit 规范、大范围改动记录日志（`docs/changelogs/`）
6. **命名规范** — 类/方法/常量/包的命名约定
7. **测试要求** — 核心路径覆盖、测试命名、禁止跳过测试
8. **Code Review（提交前必做）** — `git add` 前必须调用 code review skill 审查代码，发现问题必须修复后才能暂存
9. **Git 规范** — 分支管理、AI 不自动提交、冲突处理

## 新增目录

- `docs/changelogs/` — 变更日志存放目录（Markdown 格式）

## 影响范围

- 仅文档变更，不影响任何代码逻辑和运行时行为
- 后续所有代码变更需遵循新增的规约

## 注意事项

- 安全规约（第一节）为最高优先级，与安全冲突的其他规约让步于安全
- `docs/changelogs/` 目录下的日志文件按 `YYYY-MM-DD-<描述>.md` 命名
