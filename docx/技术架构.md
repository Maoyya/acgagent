## 3. 认证与安全架构

### 认证流程

系统采用 Gateway 统一鉴权模式，下游服务不再使用 Spring Security：

```
客户端 → Gateway(8080) → JwtAuthFilter → 验证 JWT → 注入 X-User-Id → 路由转发 → 下游服务
```

**详细流程：**

1. 客户端携带 `Authorization: Bearer <token>` 请求 Gateway
2. `JwtAuthFilter`（GlobalFilter，优先级 -1）拦截请求
3. 白名单路径直接放行：`/api/auth/**`、`/druid/**`、`GET /api/agents`、`GET /api/agents/{id}`
4. 非白名单请求解析 JWT（HMAC-SHA），提取 userId
5. 将 `X-User-Id` 和 `X-Username` 注入请求头，转发给下游服务
6. 下游服务通过 `UserContext.getUserId()` 从请求头读取当前用户 ID
7. Token 无效或缺失时返回 HTTP 401

**登录方式：**

| 方式 | 认证机制 | 说明 |
|------|----------|------|
| 用户名 + 密码 | JWT Token | BCrypt 密码校验，签发 Access + Refresh Token |
| 手机验证码 | JWT Token | 6 位验证码，5 分钟有效，未注册手机号自动注册 |
| 微信扫码 | OAuth2 + JWT | 微信开放平台授权回调后签发 Token，首次授权自动绑定/注册 |

**JWT Token 设计：**
- Access Token：有效期 2 小时，携带 userId
- Refresh Token：有效期 7 天，用于无感刷新 Access Token
- Token 签发在 acg-user 的 `JwtUtil`，验证在 acg-gateway 的 `JwtAuthFilter`

### 安全措施

| 安全项 | 实现方式 | 说明 |
|--------|----------|------|
| 认证 | Gateway JWT + JwtAuthFilter | 白名单外所有请求需携带 Bearer Token |
| 密码存储 | BCrypt（PasswordUtil） | 密码不可逆加密存储 |
| API Key 脱敏 | AgentVO.from() 中掩码 | Agent 的 apiKey 返回前端时显示为 `****` + 后 4 位 |
| CORS | CorsConfig 允许所有来源 | 开发阶段，生产环境需收紧 |
| SQL 注入防护 | MyBatis-Plus LambdaQueryWrapper | 参数化查询，禁止拼接 SQL |
| 输入校验 | Controller 层 + @Valid | 空值、格式、长度校验 |
| Sentinel 限流 | Gateway 路由级别限流 | 防止恶意请求 |

## 5. SSE 流式通信

### 对话流式输出流程

对话回复不再由 Java 直接调用 LLM，而是经 `PythonAiClient` 转发到 Python AI 引擎（acgagent-ai），Java 侧负责会话归属校验、用户消息落库、把 Python 返回的结构化 `ChatEvent` 透传给前端：

```
前端 → POST /api/chat/conversations/{id}/send
     → ChatServiceImpl（acg-chat）
       → 校验会话归属（防越权）+ Agent 存在
       → 校验 Agent 已同步到 Python（python_agent_id 非空，否则拒绝）
       → 保存用户消息到 message 表（前端历史 UI 用）
       → 创建 SseEmitter（chat.sse-timeout，默认 5 分钟）
       → 线程池异步调用 PythonAiClient.streamChat(pythonAgentId, conversationId, message, userId)
         → WebClient POST 到 Python /api/v1/chat/{agentId}/completions
         → 透传 X-API-Key + X-User-Id，body 带 conversation_id（Python 据此自管上下文记忆）
         → 逐行解析 Python SSE `data: {json}` 为结构化 ChatEvent
         → 通过 SseEmitter.send() 序列化后逐事件透传前端
       → content 事件累计文本，done 事件持久化 Assistant 消息；error 事件不落库残缺回复
```

> 会话上下文由 Python 按 `conversation_id` 自管（M1 双写），Java 不再查历史喂 LLM。

**ChatEvent 事件契约（snake_case，镜像 Python schema，前端 SSE 解析契约）：**

| `type` | 说明 | 关键字段 |
|--------|------|----------|
| `content` | 文本片段（增量） | `content` |
| `tool_call` | 工具调用 | `tool_name`, `tool_input` |
| `tool_result` | 工具返回 | `tool_name`, `tool_output` |
| `thinking` | 推理过程 | `content` |
| `error` | 错误（不持久化回复） | `code`, `message` |
| `done` | 流结束，触发落库 | `usage`（token 用量） |

Gateway 对 `/api/chat/**` 路径支持 SSE 流式转发（`Content-Type: text/event-stream`）。

## 5.1 Java ↔ Python AI 引擎集成边界

acg-chat 与外部 Python AI 引擎（acgagent-ai）之间通过 HTTP/WebClient 交互，`PythonAiClient`（`agent/client/`）是 Java 侧调用 Python 的**唯一出口**。

### 职责划分

| 域 | 真相源 | Java 侧动作 |
|----|--------|-------------|
| Agent 配置 | Java `agent` 表为主，Python 镜像 | create/update/delete 时同步到 Python，回写 `python_agent_id` |
| 对话流式 | Python 引擎生成 | `streamChat` 透传 `ChatEvent`，Java 仅落用户消息与 done 时的助手消息 |
| 知识库 / 文档 | **Python 为真相源，Java 不落库** | `PythonAiClient` 代理 CRUD + multipart 文档上传 |
| 工具 | **Python 为真相源，Java 不落库** | `PythonAiClient` 代理 list/get/create/delete |
| 提示词生成 | Python 生成 | generate / moderate / estimate 经 `PythonAiClient` 调用，模板落 `prompt_template` 表 |

### 关键约定

- **`python_agent_id` 同步锚点**：`agent` 表的 string 列，记录 Python 侧 agent id。Agent 创建/更新时 Java 调 Python 落库并回写该字段；**未同步（为空）时对话接口直接拒绝**（`ChatServiceImpl` 显式校验），保证不会用未同步的 Agent 发起对话。
- **存量迁移**：`AgentSyncMigrationRunner`（`agent/migration/`）是 `CommandLineRunner`，受开关 `python-agent.migrate-existing`（默认 `false`）控制。开启后下次启动遍历所有 `python_agent_id` 为空的 agent，逐条在 Python 创建并回写；单条失败仅记日志、不中断，可重跑。
- **请求签名**：所有 Python 请求带 `X-API-Key`（来自 `python-agent.api-key`，绝不返回前端）；对话/提示词请求额外带 `X-User-Id` 透传当前用户。
- **超时**：普通请求用 `python-agent.read-timeout`（默认 10s），流式用 `stream-read-timeout`（默认 5 分钟，对齐 `chat.sse-timeout`），均通过 reactor `.timeout()` 在调用处生效；连接超时由 `python-agent.connect-timeout`（默认 5s）在 `pythonWebClient` Bean 上预置。

### 连接配置

`PythonAgentProperties`（`config/`）绑定 Nacos `acg-chat.yaml` 中 `python-agent.*` 前缀：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `python-agent.base-url` | — | Python 引擎基础地址，如 `http://127.0.0.1:8100` |
| `python-agent.api-key` | — | 调用 Python 的 X-API-Key（与 Python `.env` 的 `ACG_AI_API_KEY` 一致） |
| `python-agent.connect-timeout` | 5000 | 连接超时（毫秒） |
| `python-agent.read-timeout` | 10000 | 普通请求读超时（毫秒） |
| `python-agent.stream-read-timeout` | 300000 | SSE 流式读超时（毫秒） |

## 6. 技术规范

### 代码规范

- **包结构：** `com.darkness.{模块}.{分层}`，分层包括 controller、service、service/impl、mapper、model、enums、constant、result、exception、util、client、dubbo、config
- **命名约定：** Controller 以 `Controller` 结尾，Service 接口以 `Service` 结尾，实现类以 `ServiceImpl` 结尾，Dubbo 实现以 `FacadeImpl` 结尾；启动类命名 `{模块}Application`
- **注解：** Controller 使用 `@RestController` + `@RequiredArgsConstructor` 构造注入，配置类使用 `@Configuration`
- **实体：** Entity 继承 `BaseEntity`，命名以 `DO` 后缀，使用 Lombok `@Data`，标注 `@TableName`
- **VO：** 命名以 `VO` 后缀，提供静态 `from(DO)` 工厂方法和 `toEntity()` 转换方法
- **注入：** 优先 Lombok `@RequiredArgsConstructor` 构造注入，禁止 `@Autowired` 字段注入

### API 规范

- **统一响应：** 所有接口返回 `Result<T>`（`code`、`message`、`data`）
- **成功码：** `code = 200`，`message = "success"`
- **异常处理：** 业务异常通过 `BizException(code, message)` 抛出 → `GlobalExceptionHandler` 捕获 → 返回 `Result<Void>`
- **REST 约定：** `GET` 查询 → `POST` 创建 → `PUT` 全量更新 → `DELETE` 逻辑删除
- **空值处理：** `Result.data` 为 null 时由 `@JsonInclude(NON_NULL)` 自动省略

### 数据库规范

- **表命名：** `sys_` 前缀表示系统表（`sys_user`、`sys_role`），业务表直接命名（`agent`、`conversation`）
- **字段命名：** 数据库 `snake_case` → Java `camelCase`，MyBatis-Plus 自动映射
- **主键：** `id BIGINT AUTO_INCREMENT`，实体使用 `@TableId(type = IdType.AUTO)`
- **逻辑删除：** `deleted` 字段（TINYINT，0=未删除，1=已删除），通过 `@TableLogic`
- **自动填充：** `created_at`（INSERT 填充），`updated_at`（INSERT + UPDATE 填充），由 `MetaObjectHandler` 处理
- **字符集：** `utf8mb4`

## 8. 配置说明

### Gateway 路由配置

### Nacos 配置管理

各服务通过 `bootstrap.yml` 从 Nacos（命名空间 `acg_agent`）拉取共享配置：

| 共享配置 | 内容 |
|----------|------|
| `common-mysql.yaml` | MySQL + Druid 连接池配置 |
| `common-dubbo.yaml` | Dubbo 协议与注册中心 |
| `common-jwt.yaml` | JWT secret 和过期时间 |

服务专属配置：`acg-user.yaml`、`acg-chat.yaml`、`acg-gateway.yaml`。

> **持久化说明：** Nacos 的配置与服务元数据**持久化到 `acg_agent` 业务库（MySQL）**，而非默认的嵌入式 Derby，也不再使用独立的 `nacos` 库（旧 `nacos` 库因数据卷非空从未被 initdb 脚本创建）。12 张 nacos 表（`config_info`/`his_config_info`/`tenant_info`/`users`/`roles`/`permissions` 等）与业务表同库，已核对无表名冲突。命名空间 `acg_agent` 是逻辑命名空间（对应 `tenant_info` 表），与「持久化用哪个物理库」是两回事。详见 `docs/changelogs/2026-06-27-nacos-persistence-to-acg_agent-db.md`。
