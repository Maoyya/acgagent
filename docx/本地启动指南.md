# 本地启动指南

## 环境要求

| 组件 | 版本 | 本文档使用的版本 |
|---|---|---|
| JDK | 21+ | OpenJDK 21.0.11 |
| Maven | 3.9+ | Apache Maven 3.9.9 |
| MySQL | 8.0 | 8.0（Docker） |
| Nacos | 2.4.3 | 2.4.3（Docker） |

---

## 第一步：启动基础设施

MySQL 和 Nacos 通过 Docker 启动：

```bash
cd docker
docker-compose up -d mysql nacos
```

启动后验证：

```bash
# MySQL — 端口 3306
docker ps | grep mysql

# Nacos — 端口 8848
docker ps | grep nacos

# 访问 Nacos 控制台
# http://localhost:8848/nacos  （账号/密码：nacos/nacos）
```

### 初始化 Nacos 配置

确保 Nacos 中存在命名空间 `acg_agent`，并在该命名空间的 `DEFAULT_GROUP` 下创建以下 6 个配置（YAML 格式）。

配置文件源码位于 `docx/nacos_config/DEFAULT_GROUP/` 目录：

| dataId | 说明 | 对应文件 |
|---|---|---|
| `common-mysql.yaml` | MySQL + Druid + MyBatis-Plus 共享配置 | `docx/nacos_config/DEFAULT_GROUP/common-mysql.yaml` |
| `common-dubbo.yaml` | Dubbo 注册中心（DUBBO_GROUP 隔离） | `docx/nacos_config/DEFAULT_GROUP/common-dubbo.yaml` |
| `common-jwt.yaml` | JWT 密钥和过期时间 | `docx/nacos_config/DEFAULT_GROUP/common-jwt.yaml` |
| `acg-user.yaml` | acg-user 专属：Druid 监控、Dubbo 协议、微信/短信、Zipkin | `docx/nacos_config/DEFAULT_GROUP/acg-user.yaml` |
| `acg-chat.yaml` | acg-chat 专属：Dubbo 协议/消费者、Zipkin | `docx/nacos_config/DEFAULT_GROUP/acg-chat.yaml` |
| `acg-gateway.yaml` | Gateway 路由规则 | `docx/nacos_config/DEFAULT_GROUP/acg-gateway.yaml` |

也可通过 Nacos API 批量导入：

```bash
for file in docx/nacos_config/DEFAULT_GROUP/*.yaml; do
  dataId=$(basename "$file")
  curl -X POST "http://localhost:8848/nacos/v1/cs/configs" \
    -d "group=DEFAULT_GROUP&tenant=acg_agent&type=yaml" \
    --data-urlencode "content@${file}"
  echo " -> $dataId"
done
```

### 初始化数据库

建表脚本位于 `acg-user/src/main/resources/db/schema.sql`，MySQL 容器启动时会自动执行。如需手动执行：

```bash
mysql -u root -proot acg_agent < acg-user/src/main/resources/db/schema.sql
```

## 第二步：构建项目

```bash
# 设置环境变量（根据实际安装路径调整）
export JAVA_HOME=/d/jdk/jdk21
export PATH=$JAVA_HOME/bin:/d/apache-maven-3.9.9-bin/apache-maven-3.9.9/bin:$PATH

# 构建全部模块（跳过测试）
cd D:/ideaproject/acgAgent
mvn clean package -DskipTests
```

构建成功后各模块 JAR 位置：

| 模块 | JAR 路径 |
|---|---|
| acg-gateway | `acg-gateway/target/acg-gateway-1.0-SNAPSHOT.jar` |
| acg-user | `acg-user/target/acg-user-1.0-SNAPSHOT.jar` |
| acg-chat | `acg-chat/target/acg-chat-1.0-SNAPSHOT.jar` |

## 第三步：启动微服务

三个服务可以并行启动，无顺序依赖。启动后需等待约 10 秒让 Nacos 服务发现完成注册。

```bash
# 启动 acg-user（端口 8081，Dubbo 20881）
java -jar acg-user/target/acg-user-1.0-SNAPSHOT.jar &

# 启动 acg-chat（端口 8082，Dubbo 20882）
java -jar acg-chat/target/acg-chat-1.0-SNAPSHOT.jar &

# 启动 acg-gateway（端口 8080）
java -jar acg-gateway/target/acg-gateway-1.0-SNAPSHOT.jar &
```

Windows 环境下在每个终端窗口分别启动，或使用后台方式：

```bash
start //b java -jar acg-user/target/acg-user-1.0-SNAPSHOT.jar
start //b java -jar acg-chat/target/acg-chat-1.0-SNAPSHOT.jar
start //b java -jar acg-gateway/target/acg-gateway-1.0-SNAPSHOT.jar
```

## 第四步：验证

```bash
# 1. 注册用户
curl -s http://localhost:8080/api/auth/register \
  -X POST -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"Test123456"}'

# 2. 登录获取 token
curl -s http://localhost:8080/api/auth/login \
  -X POST -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"Test123456"}'

# 3. 获取 Agent 列表（无需认证）
curl -s http://localhost:8080/api/agents

# 4. 带 token 访问受保护接口
curl -s http://localhost:8080/api/users/me \
  -H "Authorization: Bearer <上一步拿到的token>"
```

## 端口总览

| 服务 | HTTP 端口 | Dubbo 端口 | 说明 |
|---|---|---|---|
| MySQL | 3306 | — | 数据库 |
| Nacos | 8848 | — | 服务发现 + 配置中心 |
| acg-gateway | **8080** | — | API 网关（统一入口） |
| acg-user | 8081 | 20881 | 用户 + 认证服务 |
| acg-chat | 8082 | 20882 | Agent + 对话服务 |

所有 API 请求统一通过 Gateway（端口 **8080**）进入。

## 配置加载说明

项目使用 **本地 + Nacos 远程** 混合配置方案：

```
bootstrap.yml（本地）                application.yml（本地）
┌──────────────────────┐           ┌─────────────────────────────┐
│ server.port           │           │ spring.config.import:       │
│ spring.application    │           │   - nacos:common-mysql.yaml │
│ nacos.server-addr     │           │   - nacos:common-dubbo.yaml │
│ nacos.discovery       │           │   - nacos:common-jwt.yaml   │
└──────────────────────┘           │   - nacos:acg-user.yaml     │
       ↓ 启动引导                   └─────────────────────────────┘
                                            ↓ spring.config.import
                                   ┌─────────────────────────────┐
                                   │ Nacos acg_agent 命名空间     │
                                   │                             │
                                   │ 共享配置：                    │
                                   │  common-mysql.yaml          │
                                   │  common-dubbo.yaml          │
                                   │  common-jwt.yaml            │
                                   │                             │
                                   │ 服务专属配置：                 │
                                   │  acg-user.yaml              │
                                   │  acg-chat.yaml              │
                                   │  acg-gateway.yaml           │
                                   └─────────────────────────────┘
```

| 配置项 | 放在哪 | 为什么 |
|---|---|---|
| 端口、服务名、Nacos 地址 | 本地 bootstrap.yml | 连接 Nacos 前就需要，不会变 |
| `spring.config.import` | 本地 application.yml | 声明从 Nacos 拉取哪些配置 |
| 数据源、MyBatis-Plus | Nacos common-mysql.yaml | 多服务共享，可动态调整 |
| Dubbo 注册中心 | Nacos common-dubbo.yaml | 多服务共享 |
| JWT 密钥和过期时间 | Nacos common-jwt.yaml | 多服务共享，支持动态刷新 |
| Dubbo 协议/Druid/第三方 | Nacos 服务专属配置 | 服务独有，可动态调整 |
| 路由规则 | Nacos acg-gateway.yaml | 可动态调整路由，无需重启网关 |

## 环境变量

所有配置中的敏感信息通过环境变量注入，本地开发有默认值：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_HOST` | localhost | MySQL 地址 |
| `MYSQL_PASSWORD` | root | MySQL 密码 |
| `JWT_SECRET` | acgagent-jwt-...（见 Nacos） | JWT 签名密钥 |
| `NACOS_ADDR` | localhost:8848 | Nacos 地址 |
| `ZIPKIN_ENDPOINT` | http://localhost:9411/api/v2/spans | Zipkin 端点 |
| `WX_APP_ID` | 空 | 微信开放平台 AppID |
| `WX_APP_SECRET` | 空 | 微信开放平台 Secret |
| `SMS_PROVIDER` | mock | 短信服务商（mock/真实） |

## 常见问题

### 1. 启动报 `Failed to configure a DataSource`

**原因**：Nacos 配置未加载到，数据源信息缺失。

**排查**：
- 确认 Nacos 正在运行：`curl http://localhost:8848/nacos/`
- 确认 Nacos 中 `acg_agent` 命名空间下存在 `common-mysql.yaml`
- 确认 `application.yml` 中 `spring.config.import` 配置正确
- 确认 `spring.cloud.nacos.config.namespace` 设置为 `acg_agent`

### 2. Gateway 返回 503 Service Unavailable

**原因**：下游服务未注册到 Nacos，或 Gateway 的 LoadBalancer 找不到实例。

**排查**：
- 确认 acg-user / acg-chat 已启动且日志中出现 `Started`
- 在 Nacos 控制台检查 `acg_agent` 命名空间的服务列表中是否有对应服务
- 检查 Gateway 依赖中是否包含 `spring-cloud-starter-loadbalancer`

### 3. Gateway 返回 `Invoker not found`（Dubbo 404）

**原因**：Dubbo 服务注册到了与 Spring Cloud 相同的分组，LoadBalancer 轮询到了 Dubbo 的 triple 协议端口（20881/20882）而非 HTTP 端口。

**解决**：确认 `common-dubbo.yaml` 中 Dubbo 注册中心使用了 `group: DUBBO_GROUP` 进行隔离：

```yaml
dubbo:
  registry:
    address: nacos://${spring.cloud.nacos.server-addr}?namespace=acg_agent&group=DUBBO_GROUP
    group: DUBBO_GROUP
```

### 4. Gateway 启动报 `Failed to determine a suitable driver class`

**原因**：Gateway 依赖了 `acg-common`（含 MyBatis-Plus / Druid），Spring Boot 自动配置了数据源，但 Gateway 不需要数据库。

**解决**：在 Gateway 启动类上排除数据源自动配置：

```java
@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
```

### 5. 端口被占用

```bash
# 查看占用端口的进程
netstat -ano | grep ":8081.*LISTENING"

# 终止进程（Windows）
taskkill /F /PID <PID>
```

### 6. `Could not resolve placeholder 'jwt.secret'`

**原因**：Nacos 配置 `common-jwt.yaml` 未被加载。

**排查**：
- 确认 `application.yml` 的 `spring.config.import` 中包含 `nacos:common-jwt.yaml`
- 确认 Nacos 中 `common-jwt.yaml` 内容正确
- 确认 `spring.cloud.nacos.config.namespace` 为 `acg_agent`
