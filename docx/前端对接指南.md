# 前端对接指南

本文档面向前端开发者，说明如何与 acgAgent 后端 API 进行对接。

---

## 1. 架构概览

```
浏览器 → Vite Dev Server (proxy /api) → Gateway (:8080) → acg-user (:8081) / acg-chat (:8082)
```

- 所有请求统一经过 **Gateway（端口 8080）**，前端只需对接这一个入口
- Vite 开发环境已配置代理：`/api` → `http://localhost:8080`，前端请求直接用 `/api` 前缀即可
- Gateway 根据路径自动路由到下游服务，前端无需感知后端微服务拆分

---

## 2. 统一响应格式

所有接口（除 SSE 流式接口外）均返回以下 JSON 结构：

```typescript
interface Result<T> {
  code: number    // 业务状态码
  message: string // 描述信息
  data: T         // 业务数据，错误时为 null
}
```

### 状态码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证或 Token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 注意事项

- 即使业务错误，**HTTP 状态码仍为 200**，错误通过 JSON 中的 `code` 字段区分
- Gateway 层的鉴权拦截（Token 缺失/无效）返回的是 **HTTP 401**，无 JSON 响应体
- 前端 Axios 拦截器应同时处理 HTTP 401 和业务 code 401

## 3. 认证机制

### Token 获取

通过登录接口获取 `accessToken` 和 `refreshToken`：

```json
// POST /api/auth/login 成功响应
{
  "code": 200,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9...",
    "expiresIn": 7200
  }
}
```

### Token 使用

- 需认证的接口须携带请求头：`Authorization: Bearer <accessToken>`
- Gateway 验证 Token 后，将 `userId` 注入 `X-User-Id` 请求头转发给下游服务

### Token 有效期

| Token 类型 | 有效期 |
|---|---|
| accessToken | 2 小时 |
| refreshToken | 7 天 |

### Token 刷新

accessToken 过期后，用 refreshToken 调用刷新接口获取新的 Token 对：

```
POST /api/auth/refresh
Body: { "refreshToken": "<refreshToken>" }
```

### 免认证接口

以下接口无需携带 Token：

| 路径 | 说明 |
|---|---|
| `POST /api/auth/register` | 注册 |
| `POST /api/auth/login` | 登录 |
| `POST /api/auth/refresh` | 刷新 Token |
| `POST /api/auth/sms/send` | 发送短信验证码 |
| `POST /api/auth/sms/login` | 短信验证码登录 |
| `POST /api/auth/wx/qrcode` | 获取微信二维码 |
| `POST /api/auth/wx/callback` | 微信扫码回调 |
| `GET /api/agents` | Agent 列表 |
| `GET /api/agents/{id}` | Agent 详情 |

## 4. 枚举值定义

前端开发时需对齐以下枚举：

### CommonStatus（通用状态）

| 值 | 含义 |
|---|---|
| `0` | 禁用 |
| `1` | 启用 |

用于：UserVO.status、RoleVO.status、PermissionVO.status、AgentVO.status

### MessageRole（消息角色）

| 值 | 含义 |
|---|---|
| `"user"` | 用户消息 |
| `"assistant"` | AI 回复 |

### PermissionType（权限类型）

| 值 | 含义 |
|---|---|
| `1` | 菜单 |
| `2` | 按钮 |

### AgentCategory（Agent 分类）

Agent 的 `category` 字段标识智能体类型，序列化值（`@JsonValue`）为大写字符串。

| 值 | 含义 |
|---|---|
| `"CHAT"` | 对话 |
| `"VIDEO"` | 视频 |
| `"IMAGE"` | 生图 |

- 用于：`AgentVO.category`
- 反序列化大小写不敏感，非法值回退为 `CHAT`

### PromptMode（系统提示词生成模式）

控制提示词生成 / moderation 的风格策略，序列化值（`@JsonValue`）为小写字符串（匹配 Python 侧 `PromptMode(str, Enum)`）。

| 值 | 含义 |
|---|---|
| `"acg"` | ACG 风格：拥抱二次元/动漫（仅挡暴力违法/超能力） |
| `"compliant"` | 中性专业：额外限制二次元风格 |

- 用于：`PromptTemplateVO.mode`、`PromptGenerateResponseVO.mode`、`ModerationVerdictVO.mode`，以及 `POST /api/prompts/generate`、`POST /api/prompts/moderate`、`POST /api/prompts/templates` 的 `mode` 入参
- 反序列化大小写不敏感；非法值抛 `IllegalArgumentException`，Controller 绑定时转为 `code=400`

### 5.5 Agent 模块（`/api/agents`）

#### GET `/api/agents` — 获取 Agent 列表（免认证）


```
// Response: Result<AgentVO>
```

AgentVO 结构：

```typescript
interface AgentVO {
  id: number
  name: string
  description: string | null
  avatar: string | null
  apiUrl: string            // 外部 LLM API 地址
  apiKey: string            // 响应中始终为 "******"（脱敏）
  model: string             // 模型名称，如 "gpt-4"
  status: number            // 0=禁用, 1=启用
  configJson: string | null // 已废弃，保留向前兼容
  // —— 以下为扩展字段（同步到 Python 引擎）——
  category: 'CHAT' | 'VIDEO' | 'IMAGE' | null   // Agent 分类
  systemPrompt: string | null                   // 系统提示词
  provider: string | null                       // LLM 厂商：doubao/qwen/deepseek
  temperature: number | null                    // 生成温度
  maxTokens: number | null                      // 最大输出 token 数
  topP: number | null                           // Top-P 采样
  memoryType: string | null                     // 记忆类型：conversation_window/summary/none
  memoryMaxTokens: number | null                // 上下文窗口 token 数
  capabilities: string[] | null                 // 能力标签数组
  knowledgeBaseIds: string[] | null             // 关联知识库 id 列表（Python 侧 string id）
  toolIds: string[] | null                      // 关联工具 id 列表（Python 侧 string id）
  pythonAgentId: string | null                  // 同步锚点：Python 侧 agent 的 string id，未同步时为 null
  createdAt: string
  updatedAt: string
}
```

> **注意**：`apiKey` 在响应中始终被脱敏为 `"******"`，前端不应将其用于显示或回传。
> 更新 Agent 时，传 `"******"` 表示保持原值不变，传新值表示替换。
> `pythonAgentId` 为 Java↔Python 同步锚点，**未同步（null）的 Agent 调对话接口会被拒绝**；正常展示无需关心该字段。
> `knowledgeBaseIds` / `toolIds` 中的 id 均为 **Python 侧 string id**（非 Java Long），需直接透传 `/api/knowledge-bases` / `/api/tools` 返回的 `id`。

#### POST `/api/chat/conversations/{id}/send` — 发送消息（SSE 流式）

**此接口与其他接口不同，返回的是 SSE 事件流，不是 `Result<T>` JSON 包装。**

```json
// Request
{ "content": "你好，请帮我写一段代码" }
```

前端应使用 `fetch` + `ReadableStream` 或 `EventSource`（需自行处理 POST）接收流式响应：

```typescript
// 推荐使用 fetch 方式
const response = await fetch(`/api/chat/conversations/${conversationId}/send`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': `Bearer ${accessToken}`
  },
  body: JSON.stringify({ content: '你好' })
})

const reader = response.body!.getReader()
const decoder = new TextDecoder()

while (true) {
  const { done, value } = await reader.read()
  if (done) break

  const chunk = decoder.decode(value, { stream: true })
  // 解析 SSE 数据并实时渲染 AI 回复
  // chunk 格式为 SSE 文本流，包含 AI 生成的增量内容
}
```

> **重要**：此接口不走 Axios 拦截器，需手动处理认证和错误。

## 8. 前端对接注意事项

### 8.1 Axios 拦截器

前端 `request.ts` 已配置了请求/响应拦截器：
- **请求拦截**：自动从 `localStorage` 读取 `accessToken` 并附加到 `Authorization` 头
- **响应拦截**：解析 `Result<T>` 结构，`code !== 200` 时弹出 `ElMessage.error`
- **401 处理**：清除 Token 并跳转登录页

### 8.2 SSE 流式接口

`POST /api/chat/conversations/{id}/send` 返回 SSE 流，不走 Axios，需使用 `fetch` API 手动处理。注意：
- 需手动附加 `Authorization` 请求头
- 需手动处理流式读取和解析
- 网络错误需自行捕获

### 8.3 Agent apiKey 脱敏

Agent 的 `apiKey` 字段在所有响应中都被脱敏为 `"******"`：
- 前端不应将 `"******"` 显示给用户或作为真实值回传
- 更新 Agent 时传 `"******"` 表示保持原值，传新值表示替换

### 8.4 角色与权限分配

角色和权限的分配接口采用**全量替换**模式：
- `POST /api/users/{userId}/roles` 传入的数组会完全替换原有角色
- `POST /api/roles/{roleId}/permissions` 传入的数组会完全替换原有权限
- 前端应先获取当前列表，让用户增删后，提交完整的新列表

### 8.5 权限树构建

权限数据是扁平结构，通过 `parentId` 构建树形关系。前端构建菜单时可参考：

```typescript
function buildPermissionTree(list: PermissionVO[]): PermissionTreeNode[] {
  const map = new Map<number, PermissionTreeNode>()
  const roots: PermissionTreeNode[] = []

  list.forEach(item => {
    map.set(item.id, { ...item, children: [] })
  })

  map.forEach(node => {
    if (node.parentId === 0) {
      roots.push(node)
    } else {
      map.get(node.parentId)?.children.push(node)
    }
  })

  return roots
}
```

### 8.6 跨域

Gateway 已配置 CORS（允许所有来源），开发环境通过 Vite 代理可避免跨域问题。生产环境建议通过 Nginx 反向代理统一域名。
